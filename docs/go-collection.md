# Go 发现、采集与淘汰

`serve` 在同一个 Go 进程运行串行采集调度、投稿、列表缓存生成与只读 HTTP。所有启动都跳过当前 Star 轮次，等待下一个北京时间整点，全天每小时一轮。11:10 启动等 12:00；21:10 启动等 22:00；整点启动也等下一轮。来源发现保持原十八轮计划。启动日志打印等待时刻（UTC）。列表启动后立即异步生成，此后每 10 分钟刷新，查询只读缓存；首次生成前明确返回准备中。清理与备份不受采集启动门槛阻塞。

循环约每分钟检查一次，不重叠。若一次发现耗时较长，后续检查串行继续；跨轮只处理最近轮次，不回放停机轮次。普通 Star 观测时间仍取 tick 开始时间，缺测和过期如实保留。项目和日快照在同一事务保存；同小时只替换较新观测，项目 ID、周期及观测时间护栏阻止旧结果污染新周期。

## 运行时配置

- `GITHUB_TOKEN`：仅供服务器请求 GitHub GraphQL 和 README REST API，不传给前端或镜像构建；也可使用 `GITHUB_TOKEN_FILE` 指向运行时挂载的秘密文件。读取 README 需要 Contents 读取权限；公开仓库的 404 会匿名复核，不能因 Token 缺少内容权限就判定无 README。

变量值优先于对应 `_FILE`。可用宿主权限为 0600 的私有 env 文件经 `docker run --env-file /private/runtime.env …` 注入，或把秘密文件只读挂载到容器。不要在命令行打印秘密。缺少 Token 不妨碍 HTTP 读取，下一轮上游失败会以安全诊断保存，已有有效观测不会被清零。

## 保持的业务规则

Linux.do 按顺序遍历以下七个固定公开 RSS 入口，成功后仍继续后续入口；只读取当次 RSS，不额外抓取帖子或回溯历史：

1. https://linux.do/c/develop/4.rss
2. https://linux.do/tag/2234-tag/2234.rss
3. https://linux.do/c/domestic/98.rss
4. https://linux.do/tag/1451-tag/1451.rss
5. https://rss.yicai-tech.com/rss/from/https://linux.do/c/develop/4.rss
6. https://rss.yicai-tech.com/rss/from/https://linux.do/tag/2234-tag/2234.rss
7. https://rss.yicai-tech.com/rss/from/https://linux.do/c/domestic/98.rss

七个入口属于一个 Linux.do 趋势源，提取 `description` 和 `content:encoded` 的 GitHub 仓库链接，归一化子路径、去除 `.git` 并忽略大小写去重，保留首次出现的顺序，遍历结束后统一进入候选收录。主备回退及其配置已删除，旧 `LINUXDO_RSS_FALLBACK_URL` 和 `_FILE` 变量不再生效，也不提供自定义列表配置。

Linux.do 仅收录默认分支主 README 原始内容包含大小写敏感字面字符串 `https://linux.do` 的仓库；仅在 RSS 中出现不足以收录，代码块与注释中的标识也算。确认无 README 或无标识的结果按稳定仓库 ID 缓存 24 小时，到期且 RSS 再次发现才重查。在库不持续复查，淘汰后重收录须重新校验。失败待确认，Linux.do 候选单独保存 `readmeNextAt`，不阻塞同仓库的 GitHub 候选；主机冷却仍共享。上线前先完成[存量清洗](linuxdo-cleanup.md)。

Star 全天逐小时采样；GitHub 日榜、Linux.do 继续按 18 时段发现（09:00–21:00 每小时，其余时间每两小时）；GitHub 周月榜、HelloGithub all/featured、OpenGithubs 日周月榜仍每日北京时间 09 点到期。每 tick 解析最多 20 条待收录身份，采样最多 100 个不同仓库；同仓库两类型共享一次结果和 24 小时元数据刷新，各自保存独立周期和历史。新类型收录只可复用本轮已成功的单个真实观测，其入库时间和保护期仍从本次收录开始。

失败至少 5 分钟后重试，服从更长主机冷却；持久化 pending、来源与 HelloGithub 详情进度、nextAt、blockedUntil 在重启、换轮和重新发现后继续有效。同主机请求开始间隔至少 2 秒；GitHub 20 秒、其他 15 秒超时覆盖响应正文，正文上限 2,000,000 字节。GitHub GraphQL 整体请求失败的主机冷却、限流最低冷却均为 5 分钟并遵守更长 Retry-After/reset。GraphQL 部分成功仍保存成功仓库。

采样策略版本 4 保留 `effectiveAt` 与 `hourlyDaytimeAt`，增加 `hourlyAt`，从升级进程下一整点开始执行全天小时制。旧历史按当时的采样计划判断，来源发现不随 Star 新计划重排；已有失败重试和主机冷却不缩短。新鲜度沿用 10 分钟宽限。

趋势窗口以项目最新成功快照为终点，24/72/168/720 小时分别取全小时、每 3 小时、每 6 小时、每日零点，均额外包含最新快照；按北京时间采样轮次取点，保留真实观测时间。维护先核对各窗口取点并集，再永久清理其他快照，包括存量历史；超过当前时间 30 天的快照仅保留项目最新一条。采集失败期间不继续稀疏化其最近有效窗口。摘要、详情和淘汰评分统一使用窗口选点，计划删除不算缺测。

全量列表仅按追踪类型查询，筛选排序由前端处理。后台同时缓存 JSON 与 gzip，每类完整生成后整体替换；生成失败记录错误并继续提供上次版本。响应 `asOf` 是结果生成时间，浏览器仍 `no-store`。详情历史按需读取，可以比列表更新；页面不轮询，准备中也只提示手动重试。

每次发现共用 3 分钟预算，HelloGithub 详情最多 20 次；预算不足延后，不计来源失败。Linux.do 七个入口共享预算，按域名共用冷却；直连域名冷却不阻止代理域名。部分失败仍处理成功候选，同时按一个来源记录入口编号及安全错误，至少 5 分钟后重试整组。全部入口解析成功（包括全部为空）才刷新整组成功时间并恢复正常调度；部分完成保留上次成功时间。冷却跳过或预算耗尽不新增请求失败，也不清除已有真实失败，已发现候选仍保留。预算耗尽至少 5 分钟后重试；两域名都冷却时不早于最早可请求时间。不保存逐入口重试状态，每次从列表开头遍历。日志和 HTTP 只保存安全诊断。

GitHub 的 `user-attachments` 路径属于附件，发现与投稿共用的链接解析器会直接排除；每次进入收录处理时也复验已持久化的 pending，将此类旧候选移出队列并保存，即使本轮没有新的发现。

尚未收录的候选在 GitHub 明确返回仓库不存在后，同轮匿名请求仓库 REST API 复核；只有匿名请求也返回 404 才结束本次收录，不能据此断言仓库已删除。按小写仓库地址在 `system_state` 缓存公开不可访问结果 24 小时，两种追踪类型共享；缓存、移出候选及收录状态事务提交。缓存期间自动发现或已有 pending 直接跳过，不延长到期时间；到期不主动检查，再次被趋势源发现才重查。主动投稿绕过该缓存，确认公开可访问后清除投稿地址及规范地址缓存，包括合并投稿；README 资格缓存仍按原规则处理。匿名可访问时复用公开资料并核对已有稳定仓库 ID；网络、限流、权限、服务及不确定响应保留重试。此规则不删除已有追踪项目或历史，也不把 README 文件自身的 404 当成仓库不可访问，详见 [ADR-0010](adr/0010-unavailable-admission-candidates.md)。

候选身份解析、README 判定及首次观测属于 `admission`，已有项目观测属于 `collection`，两者按追踪类型独立记录。页面将候选失败显示为“部分候选暂未收录，后台将重试”，趋势源请求失败单独提示，项目采样失败才提示“更新异常”。明确结束及命中不可访问缓存属于正常处理完成；admission 失败从最终仍待重试的候选汇总，保留同类型及其他类型的真实异常，包括尚未到重试时间的失败。新版 collection 状态带版本 2；旧版混合状态在查询时依据该类型所有项目的实际错误兼容展示，不受前端筛选影响，也不等待下一采样时段才纠正提示。旧失败中超出项目实际错误的部分，仅在仍存在合法待收录候选时作为候选提示；无需修改 schema 或重写历史。

每日最近一次北京时间 04 点清理按类型各自追赶，目标 500 项。未满 24 小时、过期、真实跨度不足 24 小时或任一窗口不可比均暂缓淘汰。保留评分仍按四窗口实际日均增长和 0.6/0.25/0.1/0.05 权重，评分时负数按零，页面保留真实负数。淘汰只删除本类型当前周期；再次收录创建新周期。查询严格最近 30 天，物理清理只删完整 UTC 日。

## 验证

`go test ./...` 在真实临时 SQLite 上通过调度入口和公开 HTTP 验证启动门槛、跨午夜及更长冷却、共享类型独立历史与重试、100 仓库批次、最新轮次与缺测、多入口遍历、去重、部分失败与整组重试、冷却/解析/预算、保护期淘汰和重收录，以及旧周期结果隔离。采集变更在生产以新的成功时间和真实观测验收；历史数据可读只证明查询正常。

## 项目网站

完整仓库资料查询同时获取 GitHub Homepage，保存在 `homepage` 字段并由项目接口返回。仅项目详情在简介与 Topics 之间展示链接；未设置或无法作为 HTTP/HTTPS 网站打开时隐藏。新收录首次保存，存量随现有至少 24 小时的资料刷新补齐并同步修改或清空；仅采 Star 时保留已有值，不单独全量补抓。
