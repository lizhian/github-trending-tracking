# Go 发现、采集与淘汰

`serve` 在同一个 Go 进程运行串行调度循环和只读 HTTP。所有启动都跳过当前轮次，严格等到进程启动之后的下一个北京时间应采时段：01、05、09、11、13、15、17、19、21 点。11:10 启动等 13:00；21:10 启动等次日 01:00；整点启动也等下一轮。启动日志打印等待时刻（UTC）。HTTP 可立即读取已有 SQLite，清理与备份不受这道采集门槛阻塞。

循环约每分钟检查一次，不重叠。若一次发现耗时较长，后续检查串行继续；跨轮只处理最近轮次，不回放停机轮次。普通 Star 观测时间仍取 tick 开始时间，缺测和过期如实保留。项目和日快照在同一事务保存；同小时只替换较新观测，项目 ID、周期及观测时间护栏阻止旧结果污染新周期。

## 运行时配置

- `GITHUB_TOKEN`：仅供服务器请求 GitHub GraphQL 和 README REST API，不传给前端或镜像构建；也可使用 `GITHUB_TOKEN_FILE` 指向运行时挂载的秘密文件。读取 README 需要 Contents 读取权限；公开仓库的 404 会匿名复核，不能因 Token 缺少内容权限就判定无 README。
- `LINUXDO_RSS_FALLBACK_URL`：可选 RSS 备用入口；也可通过 `LINUXDO_RSS_FALLBACK_URL_FILE` 提供。主入口失败或冷却时才使用，合法空 RSS 算成功，下次到期仍优先主入口。实际地址不能写入版本库、公开配置或日志。

变量值优先于对应 `_FILE`。可用宿主权限为 0600 的私有 env 文件经 `docker run --env-file /private/runtime.env …` 注入，或把秘密文件只读挂载到容器。不要在命令行打印秘密。缺少 Token 不妨碍 HTTP 读取，下一轮上游失败会以安全诊断保存，已有有效观测不会被清零。

## 保持的业务规则

Linux.do 仅收录默认分支主 README 原始内容包含大小写敏感字面字符串 `https://linux.do` 的仓库；仅在 RSS 中出现不足以收录，代码块与注释中的标识也算。确认无 README 或无标识的结果按稳定仓库 ID 缓存 24 小时，到期且 RSS 再次发现才重查。在库不持续复查，淘汰后重收录须重新校验。失败待确认，Linux.do 候选单独保存 `readmeNextAt`，不阻塞同仓库的 GitHub 候选；主机冷却仍共享。上线前先完成[存量清洗](linuxdo-cleanup.md)。

GitHub 日榜、Linux.do 与 Star 按九时段发现/采样；GitHub 周月榜、HelloGithub all/featured、OpenGithubs 日周月榜仍每日北京时间 09 点到期。每 tick 解析最多 20 条待收录身份，采样最多 100 个不同仓库；同仓库两类型共享一次结果和 24 小时元数据刷新，各自保存独立周期和历史。新类型收录只可复用本轮已成功的单个真实观测，其入库时间和保护期仍从本次收录开始。

失败至少 30 分钟后重试，服从更长主机冷却；持久化 pending、来源与 HelloGithub 详情进度、nextAt、blockedUntil 在重启、换轮和重新发现后继续有效。同主机请求开始间隔至少 2 秒；GitHub 20 秒、其他 15 秒超时覆盖响应正文，正文上限 2,000,000 字节。限流至少冷却 1 小时并遵守更长 Retry-After/reset。GraphQL 部分成功仍保存成功仓库。

每次发现共用 3 分钟预算，HelloGithub 详情最多 20 次；预算不足延后，不计来源失败。Linux.do 主备共享预算、各自主机冷却独立，日志和 HTTP 只保存安全诊断。

GitHub 的 `user-attachments` 路径属于附件，发现与投稿共用的链接解析器会直接排除；每次进入收录处理时也复验已持久化的 pending，将此类旧候选移出队列并保存，即使本轮没有新的发现。真实仓库地址暂时不可访问仍按原规则重试，不因 404 删除已有追踪项目或视为 README 不符合。

候选身份解析、README 判定及首次观测属于 `admission`，已有项目观测属于 `collection`，两者按追踪类型独立记录。页面将候选失败显示为“部分候选暂未收录，后台将重试”，趋势源请求失败单独提示，项目采样失败才提示“更新异常”。新版 collection 状态带版本 2；旧版混合状态在查询时依据该类型所有项目的实际错误兼容展示，不受当前筛选与分页影响，也不等待下一采样时段才纠正提示。旧失败中超出项目实际错误的部分，仅在仍存在合法待收录候选时作为候选提示；无需修改 schema 或重写历史。

每日最近一次北京时间 04 点清理按类型各自追赶，目标 500 项。未满 24 小时、过期、真实跨度不足 24 小时或任一窗口不可比均暂缓淘汰。保留评分仍按四窗口实际日均增长和 0.6/0.25/0.1/0.05 权重，评分时负数按零，页面保留真实负数。淘汰只删除本类型当前周期；再次收录创建新周期。查询严格最近 30 天，物理清理只删完整 UTC 日。

## 验证

`go test ./...` 在真实临时 SQLite 上通过调度入口和公开 HTTP 验证启动门槛、跨午夜及更长冷却、共享类型独立历史与重试、100 仓库批次、最新轮次与缺测、主备/解析/预算、保护期淘汰和重收录，以及旧周期结果隔离。采集变更在生产以新的成功时间和真实观测验收；历史数据可读只证明查询正常。
