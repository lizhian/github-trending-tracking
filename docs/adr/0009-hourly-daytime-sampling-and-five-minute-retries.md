# 白天逐小时采样与五分钟重试，保留旧历史和上游冷却

2026-10-29，用户确认提高观测频率、缩短失败后的等待，并扩大 Linux.do 候选发现范围。Star、GitHub Trending 日榜、Linux.do RSS 改为北京时间 09:00–21:00 每小时，其他时段每两小时，即 01、03、05、07、09 至 21 每个整点、23 点，共 18 轮。Linux.do 主入口改为 `https://linux.do/c/develop/4.rss`，保留主 README 的 `https://linux.do` 标识准入、备用入口及已有项目，仅解析当次 RSS，不回溯帖子。其他趋势源仍每日 09 点，元数据仍随采样每 24 小时刷新。

趋势源、候选、README 和 Star 失败至少 5 分钟后重试；GitHub GraphQL 整体请求失败及检测到限流的最低主机冷却也改为 5 分钟，更晚的 Retry-After 或额度重置时间继续优先。投稿仓库资料和 Linux.do 阶段各最多尝试 3 次，间隔至少 5 分钟，限流不计次数。普通采集无次数上限。

直接替换全局时刻表会将过去的正常间隔误判为缺测，因此保留原小时制生效边界，并记录本次新计划的独立生效边界；旧历史按当时规则计算缺测和窗口完整性，不重写快照。新边界为升级进程能够采集的下一应采时段，沿用重启等待下一轮、跨轮只处理最近一轮及 10 分钟过期宽限。

GitHub 日榜和 Linux.do 的正常来源下一执行时间按新计划重排；既有候选、来源、投稿失败重试时间继续有效。持久化主机冷却只记录最终截止时间，无法区分本地旧下限与上游要求，故已有冷却自然结束，不能因升级而缩短；后续新失败采用新下限。

本决策调整 ADR-0003/0004/0005/0007/0008 的相关时段、重试下限与主 RSS，其余容量、保护期、共享采集、收录资格和淘汰规则继续有效。实施任务：[#33](https://github.com/lizhian/github-trending-tracking/issues/33)。
