# 以禁止自动扣费为运行约束

容量数值与每小时采样要求已由 [ADR-0003](0003-scheduled-sampling-and-500-projects.md) 调整；禁止自动扣费和其余约束继续有效。下文保留第一阶段决策背景。

[ADR-0005](0005-go-sqlite-docker-runtime.md) 已接受自有服务器 Go + SQLite + Docker 的迁移目标，替代下文的 Workers + D1 路径与严格免费要求；允许既有服务器及明确批准的固定费用，继续禁止新增自动按量扣费。切流实施前现有生产仍按 Cloudflare 流程运行。

2026-10-28 确定：项目坚持免费，禁止启用任何可能自动按量扣费的产品；有免费额度但超额收费的产品也不符合约束，因此当前方案排除 R2。沿用 ADR-0001 的 1000 项目标容量，保留每小时真实 Star 快照、滚动 30 天及四个趋势窗口的计算精度，通过减少重复计算和读写优化资源使用。

访问规模以个人或小范围分享为目标，列表允许延迟 10 分钟，接受免费运行存在访问容量上限。每小时采样是运行目标，上游失败或额度耗尽时允许真实缺测、过期数据及必要时暂停服务，保留 ADR-0001 的保护期与容量规则。

第一阶段沿用 Workers + D1，减少重复计算和读写；KV 仅在实测证明有帮助时引入，若 Workers 优化后仍不能满足 CPU 额度，再讨论免费计算后备。API 仅供本站，可同步调整内部结构。查询严格过滤最近 30 天，物理记录按整日删除，可多留约一天，以免逐小时重写边界日；正常清理失败时物理删除也可能延迟。这些决定不代表已通过 Workers Free 的生产 CPU 验证。
