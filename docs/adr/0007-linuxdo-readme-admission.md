# 以主 README 判断 Linux.do 收录资格

采样时段、重试下限及 Linux.do 主 RSS 的后续调整见 [ADR-0009](0009-hourly-daytime-sampling-and-five-minute-retries.md)；下文保留原决策背景。

2026-10-29，用户确认以 GitHub 默认分支上被 GitHub 识别的主 README 判断 Linux.do 收录资格，避免把帖子中的依赖和示例误认作社区开源项目。RSS 仍提取所有仓库链接作为候选，但原始 README 必须包含大小写敏感的字面字符串 `https://linux.do` 才允许收录；代码块和注释中的出现同样算数，不扩展检查其他语言版本或文件。本决策补充 ADR-0004，实施任务为 [#27](https://github.com/lizhian/github-trending-tracking/issues/27)。

成功读取但未包含标识，或确认仓库公开可读而主 README 缺失，均不符合资格。README 404 通过匿名仓库和 README 请求复核，确认稳定仓库 ID 一致，避免 Token 权限造成的伪 404。网络、权限、限流、服务错误及无法确认仓库可访问的 404 均待确认，不能因此删除存量；新项目暂不收录，至少 30 分钟后重试并服从更长主机冷却。

不符合结果按 GitHub 稳定仓库 ID 在 `system_state` 持久缓存 24 小时，不保存正文；清洗结果共用此缓存。缓存期间 RSS 再次发现不重复请求 README，到期后只有 RSS 再发现才重新校验，不主动扫描到期仓库。README 重试只影响 Linux.do 候选，同主机冷却仍共享。只在首次收录、淘汰后重新收录和本次一次性清洗时校验，在库项目不持续复查 README。既有 pending 和本轮 Star 观测复用都不能绕过准入。

上线前暂停全部采集与常规淘汰、历史裁剪，页面查询和备份继续。`serve --linuxdo-cleanup` 在同一独占写入进程内先建立并验证独立的一致备份，再冻结全部存量 Linux.do 项目的 ID、周期及稳定仓库 ID，每轮最多处理 20 项。明确不符合者删除 Linux.do 当前周期及其历史，符合者保留原周期和历史，不影响同仓库 GitHub 类型。缓存、删除和单项进度事务提交，中断后继续；待确认项目保留并重试，全部项目得到明确结果后才算清洗完成。清洗不受普通淘汰保护期限制。

普通启动若存在 Linux.do 存量而没有完成标记，只提供查询和备份；全新且无 Linux.do 存量时直接标记完成。维护模式完成后仍不自动恢复，核对报告后重启普通模式，按 ADR-0005 等待下一应采时段。回退优先用包含准入校验的兼容 Go 版本；恢复清洗前备份后必须重新清洗，不恢复无准入保护的旧采集。无需新增数据库表或修改 schema 版本。
