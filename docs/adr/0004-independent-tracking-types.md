# 按发现体系独立追踪，共享仓库采集

2026-10-28 确定：GitHub 与 Linux.do 是独立的追踪类型。同一 GitHub 仓库可在两类中各有一个追踪项目；两类分别计算入库时间、保护期、追踪周期、趋势和保留评分，分别执行 ADR-0003 的 500 项软目标，继续遵守 ADR-0001 的暂缓淘汰规则。一类淘汰不影响另一类。这样既能观察不同发现体系中的项目，又能避免重复请求同一仓库。

`projects.type` 取值为 `github` 或 `linux.do`，`repo_id` 保存现有 GitHub GraphQL 稳定节点 ID，项目 `id` 由类型与仓库 ID 组成。现有数据归入 GitHub 类型并保留追踪周期及历史。元数据与 Star 采集按仓库共享，实际采集结果写入该仓库当前存在的各类追踪项目；新类型独立开启周期，不复制另一类此前积累的历史。

Linux.do 默认从指定的 <https://linux.do/tag/2234-tag/2234.rss> 发现仓库，并允许在主入口查询失败时使用可配置的备用 RSS 入口；两者仍属于同一个 Linux.do 趋势源。抓取时段与 GitHub 趋势日榜一致。解析 RSS 正文中的全部有效 GitHub 仓库链接，包括依赖与示例；仓库子路径归一为所属仓库，同仓库去重，不额外抓取帖子或回溯历史。每次在 RSS 中发现都刷新该类型的最近上榜时间；淘汰后再次发现允许重新收录，开启新追踪周期。

备用入口沿用原 RSS 正文格式，复用 `description` / `content:encoded` 的解析。主入口非 2xx、网络异常、超时、读取或 RSS 解析失败时回退；合法空 RSS 或零仓库仍算成功。任一入口成功即本轮发现成功，下一次到期仍优先主入口；主入口处于主机冷却时直接尝试备用入口。两个入口都失败才报告整条来源失败，诊断区分主、备用入口并仅使用安全错误信息，至少 30 分钟后重试，各自主机更长的冷却独立生效；整轮发现预算耗尽则延后执行，不另开预算。

`LINUXDO_RSS_FALLBACK_URL` 为可选 Worker 配置，空值保留仅查询主入口的行为。实际地址仅保存在被 Git 忽略的 `.env.deploy.local`，部署脚本通过标准输入写入同名 Worker Secret；源码、示例、生成配置和远程仓库均不包含实际地址。本地 Worker 可在被忽略的 `.dev.vars` 中设置该变量。未在本地提供该值时，部署脚本保留生产已有 Secret；要关闭已启用的生产回退，显式删除该 Secret。

同一仓库每个采样轮次成功获取一次 Star 结果，元数据共用现有 24 小时刷新规则；失败沿用现有重试规则。另一类型在轮次中途首次收录时，复用本轮已成功获取的单个观测并保留真实观测时间，入库时间及保护期仍从本次收录开始。例如 11:00 已观测、12:00 首次被 Linux.do 收录，则其首个快照仍标记 11:00，入库时间为 12:00，13:00 两类共同更新；不复制 11:00 之前的历史。本轮尚无成功观测时立即采集。

批次上限改为最多 100 个不同仓库，替代 ADR-0003 中“每批最多采样 100 项”的项目计量单位。同一仓库在两类中同时存在时同步写回，因此一批最多更新 200 个追踪项目；两类历史仍各自保存。

列表、统计、语言与 Topics 筛选项及类型相关运行状态均按当前追踪类型展示；共享仓库请求失败影响对应的两类项目，Linux.do RSS 失败只影响 Linux.do 发现。

本决策将 ADR-0003 的容量目标应用于每种追踪类型，其采样计划及 ADR-0002 禁止自动扣费的约束继续有效。
