# 通过持久化队列异步处理仓库投稿

[ADR-0011](0011-remove-listing-time.md) 删除了下文的最近上榜和尚未上榜语义，相关字段通过后续迁移移除；投稿流程继续有效。

采样时段、重试下限及 Linux.do 主 RSS 的后续调整见 [ADR-0009](0009-hourly-daytime-sampling-and-five-minute-retries.md)；下文保留原决策背景。

2026-10-29，用户要求允许匿名访客提交 GitHub 仓库地址，无需登录或人工审核，经过基本频率限制后自动处理。用户已确认面向 Go + SQLite 版本：HTTP 请求先将投稿写入独立持久化队列表，再由后台 goroutine 获取仓库资料并处理收录，避免请求响应依赖 GitHub 请求完成。此决定补充 ADR-0005 原先“不引入队列”的范围；普通采集的重启恢复语义不因此改变。

投稿目标是进入 GitHub 追踪类型，并在符合 Linux.do 收录资格时进入 Linux.do 追踪类型。README 资格校验、缓存与存量清洗由关联对话“校验并清洗 Linux.do 项目”负责，遵循 ADR-0007；本次只负责投稿入口、队列消费和对该能力的集成。

投稿直接收录到现有 GitHub 追踪类型，沿用采样、保护期和淘汰规则，但不构成趋势源上榜。只有投稿、尚未被趋势源发现的项目没有最近上榜时间；重复投稿既不刷新最近上榜，也不重置保护期。实现须支持缺少最近上榜时间的数据与页面展示，不能以投稿时间代替。

接受 `https://github.com/owner/repo` 仓库地址，兼容末尾 `/`、`.git` 和查询参数；不接受仓库子页面地址或私有仓库。公开 fork 和归档仓库也可投稿。

同仓库有未完成投稿时合并请求；已经收录的类型不重复创建，缺少的 Linux.do 类型仍按资格处理。淘汰后允许重新投稿，成功收录开启新追踪周期。

投稿弹窗先显示已接收，再展示本次处理状态，分别说明 GitHub 收录与 Linux.do 判定结果；暂不增加投稿历史或管理页面。仓库资料获取成功后先完成 GitHub 收录，Linux.do 校验不阻塞它；README 不符合只影响 Linux.do 收录，请求失败则等待重试。

暂时性请求失败最多尝试 3 次，间隔至少 30 分钟；GitHub 限流服从冷却时间且不消耗次数。明确无法访问的仓库直接返回失败，失败后允许重新投稿。服务重启后继续处理未完成投稿，无需等待普通采样时段；并发处理必须共享现有 GitHub 请求间隔和冷却约束。

每个 IP 每分钟最多提交 5 次，全站最多保留 100 条未完成投稿；超过限制提示稍后再试。

投稿复用 README 的 24 小时不符合缓存，命中时直接显示不符合，不重新请求。缓存到期本身不触发检查；之后再次投稿可以触发校验，补充 ADR-0007 中由 RSS 再次发现触发的入口。已经收录的 Linux.do 项目不因重复投稿重新检查 README。

GitHub 已收录但 README 校验最多尝试 3 次仍失败时，结束本次投稿处理，显示“GitHub 已收录，Linux.do 资格待确认”，保留 GitHub 追踪项目及历史。待确认不等于不符合，之后允许重新投稿重试；GitHub 收录成功后不因 Linux.do 失败而回滚或重复开启追踪周期。

已结束的投稿结果保留 7 天供查询，到期后清理；未完成投稿继续保留。清理只影响投稿记录，不影响追踪项目及 Star 历史。

2026-10-29，用户已确认完整理解并要求实施。开发任务见 [#28](https://github.com/lizhian/github-trending-tracking/issues/28)。

数据库以 `listed_at=0` 表示尚未上榜，公开接口返回 `null`；不重建项目表，以保留历史外键。新增 schema 版本 4 和离线 `migrate` 命令，投稿与收录进度在同一事务提交；同一进程的采样和投稿消费共享调度锁及上游冷却。
