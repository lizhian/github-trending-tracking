# 趋势随当前时间滚动，不可访问仓库按持平计算

2026-11-17，用户确认以下四项规则及整体开发计划。实施任务：[#43](https://github.com/lizhian/github-trending-tracking/issues/43)。旧规则让已不可访问仓库的历史增长长期冻结，同时因数据过期免于淘汰，导致旧增长看起来仍是当前增长。

所有项目的 24 小时、3 天、7 天、30 天趋势窗口均以当前时间为终点。明确不可访问的仓库保留最后已知 Star 总数和真实历史，以持平值参与后续窗口计算：短窗口先归零，长窗口保留尚在窗口内的增长并逐渐归零。持平值只是计算依据，不写成成功观测快照；页面保留最后成功观测时间和不可访问提示，不能将持平计算表示为持续成功采集。

仅 GitHub 明确返回不可访问时适用持平计算；404 不能区分删除与转为私有。超时、限流、服务器错误等临时采集故障仍按未知处理，保留数据过期及暂缓淘汰规则，不能把故障当成实际零增长。

不可访问本身不触发删除，但不再因数据过期免于正常淘汰。仍按既有保护期、容量目标和保留评分处理；四窗口权重保持 60%、25%、10%、5%，随窗口增长衰减降低评分。持平计算不能被“缺少新真实快照”的条件永久排除在淘汰之外；观测不足的新项目仍受原有保护。

恢复访问后延续原追踪周期，恢复真实采样，新旧真实 Star 总数的差值计入恢复时所在窗口。接受无法还原不可访问期间变化发生时刻的限制，不回填虚构的真实观测。

本决策替代 ADR-0012 中以最新成功快照作为趋势窗口终点的约定，以及 ADR-0001 中不可访问项目因数据过期暂缓淘汰的约定。实施时历史保留、列表及详情、完整性与缺测、保留评分须采用一致的新窗口语义；真实观测与持平计算依据保持可区分。

实现采用 schema 7 保存明确不可访问时间与恢复后的持平区间（仅覆盖最近 30 天所需区间），使失联超过 30 天后恢复时的真实差值仍可归入恢复窗口。真实快照数组保持原义；趋势摘要通过 `asOf` 和 `basis` 区分观测、持平计算及未知。窗口可保留左边界前最近一个符合分层规则的快照作为基准，最多额外保留一天历史。
